概念

子音三類 五個聲調總覽 活音節與死音節 五個聲調的音高曲線 說話時聲調會變 四個聲調符號 聲調的標記法 聲調規則表 母音長短

例字

日常容易念錯的字組 khaa 的五個聲調 khaao：米飯、新聞、白色 naa 的五個聲調

易錯

不能直接套用國語四聲 升調不是「最低的調」 拼音不標聲調等於沒寫 符號名稱不等於聲調

AGENTS.md：泰語聲調入門 LLM Wiki

這份檔案是給 AI 代理（Claude Code、Antigravity、Codex 等）看的「員工手冊」。 內容依據 process/requirements.md（2026-11-14 經使用者確認）。 架構依照 Karpathy〈LLM Wiki〉：raw（來源）→ wiki（AI 維護的知識頁）→ schema（本檔）。

1. 這個 Wiki 是做什麼的

  • 主題：泰語聲調入門，以聽說為主，最後附上「泰文怎麼標聲調」的規則簡介。
  • 讀者有兩種：
  • 完全沒學過泰語的同學：會看到從這個 Wiki 產生的教學簡報。
  • 使用者自己：Wiki 是期末「泰語聽說教練」專題的知識庫。
  • 使用者看不懂泰文字母，主要靠拼音。所以每個泰文字一定要附拼音和聲調名。

2. 資料夾

raw/               來源擷取筆記（一篇一檔，S01、S02…），ingest 之後不可再修改
wiki/
  index.md         全部頁面的目錄，每頁一行摘要。回答問題時先讀這裡
  log.md           只能往後加的時間紀錄（ingest / query / lint）
  concepts/        概念頁：五個聲調、音高曲線、子音三類、活/死音節…
  examples/        例字頁：同一個音念成不同聲調的例子（最小對立詞）
  pitfalls/        易錯頁：台灣學習者常搞混的地方
workflow/          產生簡報的 graph（SKILL.md）與 prompt
tools/             lint 與檢查腳本
runs/              每次跑 graph 的中間產物和檢查報告
process/           訪談紀錄、需求摘要、流程圖、反思
docs/              GitHub Pages 網站（wiki/ 由 tools/build_site.py 產生、slides/ 由 tools/render_slides.py 產生，不要手改）

3. 寫作規範

3.1 語言

  • 用繁體中文。術語第一次出現時附英文，例如：降調（falling tone）、子音分類（consonant class）。
  • 不用簡體字，也不用大陸用語。

3.2 泰文例字的標準寫法（lint 會檢查）

例字一律寫成：泰文 拼音（聲調名），意思寫在後面。

ข้าว khâao降米飯
  • 聲調名只能用這五個字：中 / 低 / 降 / 高 / 升。
  • 拼音的聲調符號要跟聲調名對得上：
聲調名 英文 泰文名稱 拼音標法 例
中 mid สามัญ 不加符號 naa
低 low เอก à（重音符 grave） nàa
降 falling โท â（抑揚符 circumflex） nâa
高 high ตรี á（尖音符 acute） náa
升 rising จัตวา ǎ（倒抑揚符 caron） nǎa
  • 長母音寫兩個字母（aa、ii、uu、ee、oo），短母音寫一個。
  • 聲調符號標在音節的第一個母音字母上：khâao、klâi、hǐu。
  • 送氣子音寫 kh / ph / th，不送氣寫 k / p / t。 有些教學網站把不送氣音寫成 g / bp / dt（例如 glai），收進 Wiki 時要統一改成本規範的寫法（klai），並在 log 記一筆。
  • 同一個泰文字在整個 Wiki 裡，拼音和聲調必須一致。

3.3 頁面格式

每一頁都用這個骨架：

---
title: 頁面標題
type: concept | example | pitfall
sources: [S01, S05]
updated: YYYY-MM-DD
---
# 頁面標題

一句話說明這頁在講什麼。

（內文）

## 相關頁面
- [[slug]]

## 來源差異            ← 只有來源說法不一致時才寫
- 說法甲（S06，C 級）：…
- 說法乙（S02，A 級）：…
- **採用：S02**，理由：…

## 參考資料
- S02 · raw/S02-tumtavitikul-1995.md · https://...
  • 頁面之間用 [[slug]] 連結，slug 就是檔名去掉 .md（全部小寫、用連字號）。
  • 出處的粒度：每頁最後列參考資料（使用者的選擇）。 參考資料只能列 raw/ 裡真的有的來源編號。

4. 來源與可信度

每篇來源在 raw/ 的 frontmatter 都要標 tier：

等級 類型 例
A 語音學論文、學術期刊、研討會論文 JIPA、ICPhS
B 大學教材、大學網站、百科 UCLA、LMU、NIU SEAsite、Wikipedia
C 商業教學網站、部落格 語言學習 App 的部落格

來源說法不一致時，以等級較高的為準（A > B > C），落敗的說法寫進該頁的「來源差異」，不能直接刪掉。 如果同一等級的來源說法不一樣，兩種都保留，並標示「尚無定論」。

raw/ 存的是擷取筆記，不是全文：記下書目資料、網址、擷取日期和重點。 這是因為 repo 是公開的，原文有版權。要查證時以網址上的原文為準。 raw/ 只放公開資料，不放個資，也不放使用者的上課講義。

5. 操作

Ingest（一次一篇）

  1. 把來源的擷取筆記存成 raw/Sxx-簡稱.md，標好 tier。存好之後就不能再改。
  2. 把這篇的重點跟使用者簡短對一下。
  3. 更新或新增相關的 concepts / examples / pitfalls 頁面，並在每頁的「參考資料」加上這篇。
  4. 跟現有頁面比對：新來源的說法如果跟舊頁面不同，照第 4 節的規則處理，寫進「來源差異」。
  5. 更新 wiki/index.md。
  6. 在 wiki/log.md 最後加一筆：## [YYYY-MM-DD] ingest | Sxx 標題，列出動了哪些頁。
  7. 跑 python3 tools/lint_wiki.py，通過後 git commit -m "ingest: Sxx ..."。

Query

  • 先讀 wiki/index.md，再讀相關頁面，回答時註明根據哪幾頁。
  • Wiki 裡沒有的內容，不要用自己的知識補：直接說「Wiki 裡沒有」，並建議要 ingest 哪類資料。
  • 好的回答可以存回 Wiki（例如存成新的 pitfalls 頁），並記進 log。

Lint（使用者選的三項＋基本結構檢查）

執行 python3 tools/lint_wiki.py，會檢查： 1. 斷鏈與孤兒頁：[[連結]] 指到不存在的頁面；沒有任何頁面連到的頁面（index.md 不算）。 2. 拼音格式不一致：聲調符號跟聲調名對不上；同一個泰文字在不同頁的拼音或聲調不一樣。 3. 來源之間的矛盾：「來源差異」區塊沒寫「採用」；採用的來源等級比落敗的來源低。 4. 基本結構：缺 frontmatter、缺「參考資料」、引用了 raw/ 裡沒有的來源編號。

語意上的矛盾（兩頁對同一件事的描述不同）腳本抓不到，每次 ingest 時由 AI 在第 5 節第 4 步人工比對。
